# Supabase Setup

Vercel cannot reliably persist writes to `data/store.json`. Use Supabase for deployed data.

## 1. Create Tables

Open Supabase SQL Editor and run:

```sql
create table if not exists public.products (
  id bigint generated by default as identity primary key,
  name text not null,
  unit text not null,
  price numeric not null default 0,
  created_at timestamptz not null default now()
);

create table if not exists public.invoices (
  id bigint generated by default as identity primary key,
  invoice_number text,
  invoice_date date not null,
  due_date date not null,
  customer_name text not null,
  customer_phone text not null,
  line_items jsonb not null default '[]'::jsonb,
  notes text not null default '',
  status text not null default 'draft',
  created_at timestamptz not null default now()
);
```

## 3. Configure Vercel Environment Variables

In Vercel Project Settings > Environment Variables, add:

```text
SUPABASE_URL=https://your-project-ref.supabase.co
SUPABASE_SERVICE_ROLE_KEY=your-service-role-key
```

Use the service role key only on Vercel serverless functions. Do not expose it as a `VITE_` variable.

## 4. Redeploy

Redeploy from Vercel after adding the variables.

The deployed app will keep using the same frontend routes and `/api/products` / `/api/invoices` calls, but data will be stored in Supabase.
